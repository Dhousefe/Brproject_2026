🧠 Mechanical Sympathy & Próximos Passos com Fastutil

O que é Mechanical Sympathy? É o princípio de projetar software de acordo com as características físicas reais do hardware onde o código é executado: linhas de cache de 64 bytes da CPU (L1/L2/L3), previsores de desvio (Branch Predictors), alinhamento de memória contígua e minimização de ponteiros dispersos que forçam a CPU a sofrer Cache Misses.

Por que Coleções Primitivas Fastutil são Críticas para MMORPGs?

  • Eliminação de Boxing/Unboxing: Um java.lang.Integer na heap consome 24 bytes (12 bytes de cabeçalho de objeto, 4 bytes de valor int, 4 bytes de padding/alinhamento e 4 bytes da referência em 64-bit com Compressed OOPs). Em contraste, um primitivo int consome exatamente 4 bytes!
  • Eliminação de Pointer Chasing (Salto Aleatório na Memória): Em um HashMap<Integer, WorldObject>, a CPU precisa seguir múltiplos ponteiros distantes na memória RAM para alcançar o valor. Em um Int2ObjectOpenHashMap da Fastutil, as chaves primitivas ficam armazenadas em arrays contíguos int[], permitindo que a CPU carregue 16 IDs por linha de cache L1 de uma só vez.
  • Pressão de GC Próxima a Zero: Ao remover o encapsulamento de objetos transitórios nas coleções de combate, os ciclos de coleta do Garbage Collector são minimizados, garantindo estabilidade milimétrica de ticks (zero micro-stutters).
